# 《可惜没如果》真实输入验证

验收链接为 https://www.bilibili.com/video/BV1rH4y1R7Rk，第一 P。本轮目标是从 URL 获取视频，再把完整演奏顺序输出为 PDF。修复沿用 `5081bdd` 的统一入口，所有新增回归均由本视频的实际失败观察触发。

## 获取

匿名获取最初返回 `public_api_unavailable`。相同环境下，固定版本 yt-dlp 的匿名内置 extractor 能获取视频。适配层没有保留默认请求头，没有解压有界 gzip 元数据，TLS 首地址失败也没有继续尝试其余已验证公开地址。

修复保留原 HTTPS、公开地址、重定向和固定 IP 检查。压缩体与解压体各限 2 MiB，不使用 Cookie、浏览器登录态或用户 yt-dlp 配置。按原生分辨率优先后，同尺寸优先 H.264。实际选择格式 `30080`，ffprobe 测得 1920×1080、H.264、30 fps、298.6 秒。下载文件共 7,569,981 字节，SHA256 为 `80f9a8d19515cf624d7d13c27ea758e88118fddb4341fa06deaad040272877fe`，与已有原生样本一致。

## 实际失败点

| 原视频时间 | 失败原因与修复 |
| --- | --- |
| 0→0.5 秒 | 竖直蓝光标与原谱蓝色横线连通。只识别竖直光标核心及细小边缘，保留横线作为谱面墨迹。 |
| 12、15、28.5、40、125 秒 | 蓝色记号附近的 H.264 浅色边缘跨过比较门槛。只允许双方近白蓝色、差异不超过 32 级且紧邻共同墨迹的边缘。 |
| 124→124.5 秒 | 三行向上移动 129 像素，新第四行进入。五线间距取整，固定比较带尺寸，保持三行有序重叠。 |
| 131 秒 | 被击中的音符变绿并伸出光标条。只有接触已识别光标的细小绿色组件才作为未知像素，必须由同位置真实互补观察覆盖。 |
| 144.5、170 秒 | 屏幕固定的半透明水印改变墨迹对比度。使用实际无谱行明亮背景记录比较阈值，弱灰色孤立压缩点不进入比较墨迹。 |
| 177.5、180 秒 | 末行裁剪混入下一行重音及连梁，后续完整行进入后裁剪边界变化。只有另一实际观察在配准位置显示这些边界外墨迹时才允许比较。打印候选优先选择边界有后续五线支持的真实整行。 |
| 199 秒 | 两像素的真实笔画在水印下变浅并孤立。孤立灰点规则限于背景对比低于 35 级的弱点，强对比细笔画必须保留。 |
| 183 秒 | 水印下的横梁只有约 23 级可见对比，30 级门槛漏检。采用 20 级背景对比；紧邻共同墨迹、双方均为浅灰且差异不超过 8 级的压缩边缘允许比较。9 至 32 级的近白灰差只允许孤立单像素，三个相邻浅灰像素的真实帧控制必须拒绝。 |

236 秒的已击中音符在光标后短暂变蓝。只把靠近光标核心的细小蓝色组件列为未知，要求后续同位置互补覆盖。原谱的长蓝色休止横线不满足尺寸门槛，仍作为墨迹比较。

标题和速度在第一行裁剪中。后续更清晰的候选必须保留已观察到的首行前缀，不能因为滚动后清晰度更高而丢掉标题。

完整运行还发现，114.5 秒的光标观察与此前更清晰的无遮挡行具有相同五线锚点，但空白裁剪边界相差 7 像素。旧规则在 124.5 秒滚动结束时误判位置变化。新增真实观察组合先复现失败，再改为用实际五线锚点约束同位置，不依赖空白裁剪边界。

132.5 秒的第二次滚动还有另一处失败。第 3 行最清晰的打印候选来自初始屏幕位置，但光标连续观察发生在第一次滚动后。现在单独保存当前位置的实际无遮挡观察，并在光标观察开始时固定该参考。打印仍选择全曲最清晰的原始裁剪。真实帧回归先缺少恢复记录，修复后保留第 3 行恢复证据。

停留窗口内按同位置累计光标观察，所有未知像素必须经真实互补覆盖，已暴露墨迹不得冲突。完整互补记录可核对同位置此前的实际无遮挡行。

152、172、183、195、215.5 秒仍有播放光标跨越滚动。后两处没有新增谱行，旧拼接记录未单独列出，但实际五线同样整体上移约 129 像素。152 秒的真实组合先复现未恢复行，再修复比较坐标跟随已证明的滚动。滚动证明要求唯一有序重叠、至少两条匹配行、至少一条双方无遮挡行，以及至少两个五线间距的共同向上位移，各行位移相差最多 2 像素。

`cursor_recoveries.motions` 保存每次实际前后窗口、时间、匹配行与五线坐标。坐标搬移不清除未知像素，后续真实光标观察必须逐点暴露它们，最后核对实际无遮挡整行。仅凭滚动或相同干净端点仍不能假定隐藏内容相同。152 秒帧上添加一个 5 像素 ghost note 的控制返回 `no_overlap`，不生成完整 PDF。打印仍保留真实原始裁剪。

实际累计光标在 28.5 和 40 秒另暴露配准排序问题。原成本先比较远离墨迹的点数，选中一像素偏移，全部可见差异达 17,011 点；真实零位移只有 503 点差异。现在先最小化全部可见墨迹差异，再比较远点，最优同得分拟合必须唯一，复核失败不搜索更差的拟合来消除内容变化。

水印背景按观察序号分别保存。`comparison_backdrop.references` 保留历史实际图，`seams.registrations.left_backdrop` 和 `right_backdrop` 引用当时使用的背景与时间。

测试图片来自原视频的实际解码帧，时间、提取命令及 SHA256 保存在 `tests/fixtures/BV1rH4y1R7Rk/provenance.json`。测试用 FFV1 无损拼接这些观察，通过统一 CLI 验证；压缩时间轴仅供定位，完整验收使用原视频时间轴。实际帧上的细音符增添与笔画删除控制仍需返回等待，不能靠比例容忍掩盖变化。

新增背景历史包含共享引用。恢复任务遍历并改写证据路径时，同一个字典会被访问多次，导致重复添加 `replay-*` 目录前缀。全量测试中的 9 项恢复失败复现了这一问题。遍历现按字典对象身份去重；不同字典中的相同路径仍分别改写，原有路径和文件完整性检查保留。
