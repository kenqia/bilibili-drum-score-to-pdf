# 整理记录与简介拒绝规则

状态：2026-10-26 用户逐项确认需求，并通过 implement 技能授权本地实施、审阅和提交；生产部署未授权。实现与验证记录见后续验证文档。

## 已确认的需求

整理记录保存结构化 JSON，包含输入链接、实际采用的设置、程序版本、时间、状态、失败阶段及错误码。成功转换保存完整 manifest。记录保留一周；PDF、预览和视频沿用现有期限。

每次提交、重试、临时重新排版分别记录，并关联原任务。记录取消、中断和简介规则拒绝。非法参数、限流等未入队请求仅记简要拒绝事件。

记录排除认证凭据、签名下载地址及其他敏感内容。“完整”指上述业务字段及 manifest，不包含原始 HTTP 认证头、能力凭据或下载器原始响应。

简介拒绝规则仅作用于服务器网站，不改变 CLI、Python 和独立 Skill 的行为。

视频简介含心形符号时拒绝整理。范围包含空心、实心、装饰心形及各种颜色、破碎、跳动、带箭头和组合爱心，例如 `♥ ♡ ❤ ❣ ❥ 💕 💔 💘 🖤 🩷 ❤️‍🔥`。使用明确字符表维护，排除表情、人手、信封和解剖心脏，例如 `😍 🥰 😘 🫶 💌 🫀`。实施时列出完整字符表供验收。

公开提示为“该视频暂不支持整理”，内部原因码为 `description_policy_rejected`，内部记录命中规则。取得有效简介后、下载媒体前检查，重试重新检查。

简介为空字符串、缺失、为 `null` 或类型异常时放行。元信息获取本身失败时仍沿用现有获取失败处理，不绕过已有元信息完整性验证。

每次操作结束后保留 168 小时，运行中持续保留。即时拒绝从拒绝时刻起算。重试不刷新旧记录期限。到期停止提供查询，并由周期清理删除；停服期间遗留记录在启动时清理。

运营者通过服务器本地命令按时间、任务 ID、成功或失败筛选并导出 JSON。记录仅服务器运营者可读，不增加网页管理后台。

日志无法写入时暂停接受新的整理和临时重新排版请求，返回服务暂不可用。已运行的任务继续收尾，已有结果继续可访问。实现不得声称磁盘故障期间仍能保证所有终态记录落盘，须提供可诊断的降级状态。

日志内容默认额度为 256 MiB，可显式配置。转换与日志的预留合并检查。日志未来写入按未写内容预算的两倍预留数据库及回滚 journal 空间，另加当前数据库大小和 64 MiB 页与索引余量，计入磁盘空闲底线检查。额度不足时暂停接收新的提交、重试和临时排版，不提前删除未满一周的记录，也不静默截断成功 manifest。容量值是初始配置，不保证容纳任意流量下一周的全部记录。

输入保存规范化业务链接，保留 BV、分 P 或短链标识，去掉无关参数和 fragment。短链解析后同时保存最终 BV 地址。非法请求只保留错误类别，不保存原始请求体。

## 当前实现与约束

- 网站提交输入仅为 `url`。临时重新排版另接收 `paper` 和 `rows`，不是首次转换的设置。
- 任务表只保存当前状态，重试会覆盖旧 attempt、摘要和错误，不能用于保留完整操作历史。
- 成功结果默认保留 24 小时，失败、取消和中断诊断默认保留 1 小时。到期会清除来源、摘要和错误。新记录必须使用独立保留期限。
- BBDownNext 元信息解析取得 B站简介，但当前返回值不保留简介。可在媒体下载前检查。
- 元信息解析由网站、Python 和 CLI 共用。实现必须显式限定网站策略，独立 Skill 不随网站自动修改。
- 本次只检查仓库文档和代码，未读取生产数据、认证或敏感日志。

## 实施方案

复用现有 SQLite 和 Python 标准库，不引入生产依赖或新服务。为每次操作保留独立记录身份，关联任务与 attempt；日志不随任务行重试或到期而覆盖。数据库保存结构化字段及 JSON 内容，本地命令输出 JSON。

记录具有独立的格式版本，至少包含以下字段组。尚未产生或无法测量的值为 `null`，不能伪造结果。

| 字段组 | 内容 |
| --- | --- |
| 身份 | 记录 ID、操作类型、任务 ID、attempt、关联原任务。未入队事件允许任务 ID 为空。 |
| 输入 | 规范化提交链接、解析后的最终链接。 |
| 设置 | 实际采用的转换与资源参数，或临时排版的纸张、目标行数等设置。 |
| 程序 | 包版本和可用的构建身份。 |
| 时间 | 接收、开始、结束、到期时刻；明确区分排队和处理耗时。 |
| 结果 | 当前状态、最终状态、失败阶段、错误码及脱敏说明。 |
| 输出 | 成功转换的完整网站 manifest；临时排版保存设置、页数及输出文件摘要，不保存 PDF 或预览字节。 |
| 简介规则 | 简介是否有效、是否命中、命中的规则与字符编码。不要求保存完整简介。 |

已接收操作先保存起始记录，再更新处理阶段与终态。并发、取消和重启恢复不得重复生成同一操作的终态记录。非法参数和限流等拒绝只记简要事件，不复制原始载荷。记录故障引发的服务暂不可用不得递归生成无界错误记录。

成功转换保存 worker 清理线上中间文件后实际交付的 manifest，保留来源 hash、PTS 等既有内容。日志中的路径和文件摘要不会延长对应文件寿命；文件到期后，记录仍可存在。

新增的持久结构必须有明确版本。需要改变服务 schema 时，提供显式升级并同步备份、核验和恢复工具，不自动打开或迁移未知版本。维护工具数据库上限由 64 MiB 调整为 512 MiB，与 256 MiB 日志内容额度及数据库开销协调。服务 schema 升至 v4，旧版本通过显式 upgrade-v1、upgrade-v2 或 upgrade-v3 入口恢复到新目录。

备份恢复保留原始记录结束与到期时刻，不刷新一周期限。恢复后的查询和清理继续遵守原期限。人工导出的 JSON 与历史备份属于运营者副本，运行服务的周期清理不会扫描或删除这些副本。

本地验收使用隔离合成任务及缩短的测试期限，不读取生产记录或认证。实施保留工作区已有的配准修改和实验。服务器切版、远端 push 和生产参数变更另行确认。

## 验收标准

1. 提交、重试、取消、中断、临时排版及未入队拒绝产生对应记录，重试不覆盖历史。
2. 成功记录的 manifest 与实际交付清单一致；失败记录保留真实失败阶段及脱敏错误码。
3. 合成敏感标记不出现在记录、查询或导出中；规范化链接正确保留分 P 和短链关系。
4. 用缩短的测试期限验证运行中保留、终态起算、重启不刷新、到期查询不可见及周期物理清理。PDF 和预览沿用原有期限。
5. 容量不足及写入故障暂停新操作；已有结果仍能访问，运行任务继续收尾。明确记录故障期间无法持久化的终态限制。
6. 心形字符表逐项命中，排除项正常通过；无有效简介时放行。命中发生在媒体下载前，公开提示与内部原因区分。
7. 相同来源的 CLI、Python 与独立 Skill 行为不因网站规则改变。重试重新取得简介并检查。
8. 备份、核验、恢复保留日志内容及原始期限；升级与回滚不覆盖原数据，未知 schema 继续拒绝。
9. 运行相关公开契约、网站生命周期和维护测试，再执行程序全量回归。真实服务器部署验收单独记录，不以本地测试替代。
