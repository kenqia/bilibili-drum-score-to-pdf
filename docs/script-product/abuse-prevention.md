# 匿名网站防滥用方案

本文记录 2026-10-24 确认的要求和第一批实现范围。用户先通过 implement 技能授权实现、验证、审阅及本地提交，随后明确要求 push 和部署。正式 v3 切换及目标机验收已完成，范围和证据见[部署记录](../experiments/2026-10-24-abuse-deployment.md)。

## 已确认的要求

- 以预防为目标，目前没有确认遭到攻击的证据。
- 保留匿名提交，不使用邀请码。
- 同一 IP 最近 10 分钟最多成功入队 10 次，最近 24 小时最多成功入队 100 次。两个窗口均采用滚动窗口。
- 新提交和显式重试成功入队时均计数，取消不退还次数。格式错误、额度已满或服务拒收入队不计数；入队后转换失败仍计数。
- 超额后等待额度恢复，不提供验证码绕过额度的通道。
- 不增加全站每日提交额度。该决定不取消现有并发、排队、存储和资源限制。
- 任务到期后，身份记录再保留 30 天，期间旧链接返回 410；之后清除身份记录，旧链接返回 404。该保留期不延长 PDF、预览、来源或诊断的现有期限。
- 提供应急暂停提交开关，仅供运营者使用。暂停时拒绝新提交和显式重试；已有任务继续处理，查询、下载和取消仍可用。关闭开关后恢复接收。

## 第一批实施范围

以下范围按用户确认的规则实施。

- 实现已确认的提交额度、身份记录清理和应急暂停提交规则。
- 沿用同一 IP 最多一个未完成任务。共享出口的用户共享该限制与提交额度，不增加账户、邀请码或绕过额度的验证码。
- 额度和暂停判断在服务端执行；重启不重置有效窗口内的提交计数。超额响应说明等待时间。
- 暂停开关使用受权限保护的本机运维方式，不新增公开管理接口。
- 第一批保持本地实现、文档和针对性验证；生产切换另行授权。

## 验收重点

下列检查通过合成任务、HTTP 和本机维护命令验证。最终命令与结果见[验证指南](../verification.md#匿名网站防滥用)。

- 验证滚动窗口边界、并发提交、提交与重试的共同计数、取消不退次数，以及拒收入队不扣次数。
- 验证应用重启后额度仍有效，且不读取或记录真实认证数据。
- 验证暂停期间的新提交与重试被拒收，已有任务、取消和合法结果访问仍按原规则工作。
- 验证到期后 30 天内返回 410，记录清除后返回 404；只清除符合条件的记录与已登记受管数据，不影响未到期任务和未知文件。
- 验证配额计数和任务身份记录的清理均有明确期限；检查数据库增长及清理查询的代价。
- 公开 HTTP 行为变更同步更新共同约束测试和网站文档。记录测试命令、结果与未覆盖风险。

## 后续安全核查

以下事项需要代码、准确依赖版本和部署状态的专项核查，第一批功能完成不代表这些风险已消除。

- 请求与下载的速率、连接限制及可信代理边界，尤其是轮询、慢连接和多 IP 请求。
- 解码进程权限、出网边界、依赖已知漏洞及异常告警。
- 不增加全站每日额度时，多 IP 持续占用转换名额的可用性风险。

## 实现与运行限制

以下行为属于本地代码，不代表本轮已核验生产配置。

- 网站只接收公开 B站 HTTPS 链接，不接收本地视频上传。
- `src/drum_score/jobs.py` 在同一 SQLite 写事务内检查滚动额度、未完成任务和存储准入，记录成功入队事件。排队取消释放未完成名额，但不删除提交事件。
- `submission_events` 只记录已有类别的 IP 摘要和成功入队时刻，不记录任务凭据。成功入队和 worker 清理时删除最近 24 小时以外的事件。`submission_control` 保存暂停状态，不增加公开管理接口。
- worker 先按原受管身份尝试清理文件，再删除超过三十天保留期的任务身份与受管登记。未知文件、替换物及无法清理的残留不因此被接管，需运营者核查，其占用仍计入 attempts 容量。
- 数据库记录删除后，空闲页可供后续写入复用，不保证数据库文件立即缩小。没有设置全站每日额度；多 IP 短期提交及遗留未知文件仍可能消耗容量。worker 停止期间不进行定期清理。
- HTTP 请求体上限为 8 KiB，接收期限为十秒。现有并发上限不能替代按时间窗口的请求限速。
- systemd 模板包含低权限、文件系统限制和资源硬限制。出网目标隔离及当前生产实际配置仍需独立核验。

新 schema 为 v3，旧 v1/v2 数据必须通过核验快照显式升级到新根。迁移、暂停/恢复与回滚见[维护指南](maintenance.md)。生产写入需单独明确授权。
