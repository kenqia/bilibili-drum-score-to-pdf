# 独立转换核心与 CLI

本页说明独立程序的 Python 与 CLI 入口。Skill 使用自己的[分发包和协议](../../skills/bilibili-drum-score-to-pdf/SKILL.md)，不与程序共享任务状态。程序通过图像处理整理视频，不调用模型，也不创建 Agent 审阅回执。自动完成不表示音乐已校对。

Issue #71 的本地资源模拟为每次转换建立独立 worker 和任务临时目录。父进程监督整个任务，PDF、预览和清单全部准备好后由父进程排他发布。Linux 守护进程在调用方异常退出后清理本次任务；它只删除启动时记录 inode 身份的目录。Windows 尚无本轮异常退出清理验收。

## 安装与运行

需要 Python 3.12 或更新版本，以及 PATH 中的 `ffmpeg`、`ffprobe`、`pdftoppm`。在独立虚拟环境安装，避免改变其他项目依赖：

```sh
python3.12 -m venv /tmp/drum-score-env
/tmp/drum-score-env/bin/pip install /absolute/path/to/bilibili-drum-score-to-pdf
/tmp/drum-score-env/bin/drum-score /absolute/path/input.mp4 --output /absolute/path/new-result
```

安装复制所需代码，运行不依赖源码仓库的当前目录。公开链接接受规范 HTTPS BV URL 或 `https://b23.tv/…` 短链接，分 P 通过完整或展开后的 BV URL 中单个正整数 `p` 指定：

```sh
drum-score 'https://www.bilibili.com/video/BV1rH4y1R7Rk?p=1' --output /absolute/path/new-result
```

短链接在受监督的匿名获取子进程中展开，最多 5 次跳转、每次网络操作超时 10 秒，并受整个转换时限和取消约束。仅允许 HTTPS b23.tv 与最终 BV 视频，逐跳核对公共 DNS，连接固定已核验 IP 并验证原 TLS 主机名。不读取响应正文、Cookie 或用户代理配置。非视频、失效、登录跳转和循环返回 `short_link_unavailable`。最终 manifest 的来源记录展开后的 BV、分 P 和实际视频信息。Python 和 CLI 只接收链接本身；网页可从分享文案中提取链接。

程序使用固定 BBDownNext 2.3.0 解析匿名播放信息，替代 yt-dlp。安装与平台要求见[安装指南](../install.md)。不读取用户 Cookie、登录态、模型认证或下载器用户配置；不使用 VPN，也不继承用户代理。输出目录必须不存在；失败后换新目录或重试，不覆盖来源及已有结果。删除独立虚拟环境即可撤销安装，不修改全局配置。

每次解析使用通过摘要校验的独立可执行文件副本和空配置。来源 BV、目标分 P、CID、完整曲长和受限标记必须可验证，拒绝互动、跳转、试看或不完整来源。部署使用 2.3.0 的 `metadata-bounded.1` 构建，普通调试响应与 HTTP 响应均设 2 MiB 上限。若必要来源响应缺失或被截断，程序明确失败，不以标题或退出码推断完整性。原始解析输出不进入日志、结果或诊断；临时播放 JSON 仅在本次私有目录读取，解析后删除。发布记录保留安全的后端名称、版本、构建名称及摘要、CID 和媒体实测信息。

## 公开 Python 契约

```python
from drum_score import convert, ConversionError

try:
    result = convert('/absolute/path/input.mp4', '/absolute/path/new-result',
                     progress=print)
except ConversionError as error:
    print(error.code, str(error))
```

`progress` 接收正在执行的阶段名，包括 `downloading`、`probing`、`sampling`、`registering`、`composing`、`paginating` 和 `complete`。本地输入跳过下载。没有可靠百分比和预计时间。转换阶段的回调异常会使转换失败；`complete` 在结果发布后通知，通知异常不会撤回已发布结果。

结果使用 JSON 可序列化字典，`status=complete`、`reliable=false`。`pdf`、有序 `pages`、`longshot` 包含输出目录相对路径、SHA-256 与字节数；`source` 区分本地来源和公开 BV/分 P；`samples` 记录实际解码 PTS、time_base、时间与原生帧 hash。派生长图不称为原生截图。来源文件移除后不得宣称仍可重建原始帧。 原生帧按解码器实际输出顺序观察，末尾延迟帧的PTS可能小于前一帧；程序保留这些实际值，不按PTS重排或重新赋时。诊断完整性检查使用原生序号及每帧统计、采样PTS的配对，不要求所有原生PTS单调。

`manifest.json` 与 Python 返回值及 CLI 成功标准输出相同。`program` 记录发行版本与包内直接子级 Python 源码文件的 SHA-256，不包含网站静态资源，不能当成整个发行产物的 hash，未安装包的源码运行以 `unknown` 表示未知发行版本。CLI 失败退出码为 2，JSON 包含 `status=failed` 和 `error.code/message`。错误不返回第三方原始异常、签名媒体地址或本地私有路径。

输出父目录创建或临时目录分配失败时，Python 抛出 `ConversionError`，CLI 返回 `conversion_failed` JSON 和退出码 2。临时目录清理失败不会覆盖已有具体错误码，也不会撤回已完整发布的成功结果。

## 时间范围与手动谱区

Python 的 `convert` 接收可选 `options` 字典，CLI 与网站使用相同语义：

| 字段 | 默认值 | 范围 |
| --- | --- | --- |
| `start_seconds` | `0` | 有限秒数，不小于零且小于完整来源时长。 |
| `end_seconds` | `null` | 留空到结尾；填写时须大于开始且不超过完整时长。 |
| `region_percent` | `null` | 自动谱区，或完整画面的 `[left, top, right, bottom]` 百分比。 |
| `ignore_fixed_overlays` | `true` | 是否自动忽略固定覆盖物对配准的影响。合成保留原始RGB与署名。 |

手动区域以完整画面左上角为原点，向右、向下增加，边界在0到100之间，右和下分别大于左和上。换算为原画面像素时向下取整，矩形须至少有一个像素。类型、非有限值、反向或空区间在提交时拒绝；实际时长与像素边界在取得媒体后核验。不接受未知字段或数值字符串。

例如，整理第15至75秒，并手动保留完整画面的左5%、上10%、右95%、下90%之间区域：

```sh
drum-score /absolute/path/input.mp4 --output /absolute/path/new-result \
  --start-seconds 15 --end-seconds 75 --region-percent 5 10 95 90
```

`--no-ignore-fixed-overlays` 关闭固定覆盖物忽略。时间区间使用左闭右开 `[start, end)`，保留区间内首帧、常规采样及实际最后一帧。原生帧仍记录来源的实际PTS与time_base，不从零重新赋时。`conversion.options` 记录规范化参数，`conversion.effective_range_seconds` 记录实际区间。开始时间大于零或填写结束时间时，程序按显式选段处理；即使填写的结束时间等于完整时长，`conversion.is_excerpt=true` 仍标记选段。`source.sha256` 与 `source.metadata` 始终指完整来源，不把选段当作完整原曲。

完整原来源超过600秒时，在匿名媒体传输前拒绝，选择短片段不能绕过；恰好600秒允许继续完整性核验。本地来源也按完整时长检查。此限制不替代下载后的实测时长、尺寸与来源hash核验。

## 资源预算

默认支持不超过600秒、单帧420万像素、派生长图2000万像素的视频。原视频上限256MiB；单任务临时文件与进程树RSS各使用1GiB采样预算。超过预算返回 `resource_limit`，取消返回 `cancelled`。既有来源和输出不覆盖。

CLI 可调整总时限和字节预算：

```sh
drum-score /absolute/path/input.mp4 --output /absolute/path/new-result \
  --timeout 600 --max-input-mib 256 --max-temp-mib 1024 --max-rss-mib 1024
```

Python 的 `convert` 接收 `limits` 字典，字段为 `wall_seconds`、`input_bytes`、`temp_bytes`、`rss_bytes`，只覆盖提供的字段。`cancel` 接收无参数函数；返回真时取消任务。`progress` 和 `cancel` 在调用进程执行，转换在新解释器执行。可执行 Python 脚本应把调用放在 `if __name__ == '__main__':` 保护内。`complete` 回调发生在发布后，回调异常不会撤回成功结果。

进程树RSS约每20ms采样，临时文件总额约每200ms扫描。采样可能漏掉瞬时峰值或短暂超额，RSS求和可能重复统计共享页；它们都不是cgroup或文件系统硬配额。`resources` 记录实际采样方式、峰值、线程环境与额度，未知值为 `null`。`metrics.peak_temp_disk` 仍只指旧解码器单张scratch帧大小，任务总临时空间应读 `resources.peak_observed_temp_bytes`。

OpenCV设置单线程，子进程环境将常用数值库线程变量设为1；不修改用户全局环境。五线与分页空白计数使用256行缓冲，合成仍保留一张有像素上限的RGB长图。当前环境没有可写cgroup和systemd用户管理器，以上是本机预算模拟，不能证明目标2GB服务器已通过。

## 支持边界与验收

目标输入为固定比例、白底纵向滚谱，包括停驻后向上推进。已验证的窄重叠视口跳动可以接续。无重叠硬切在有界原生窗口确认前后稳定完整谱页后，可按视频页序交付，并在结果数据和网站标记连续性待核对。横向移动和变焦尚未列入通用支持。检查到无法配准、没有五线谱或来源变动时明确失败；程序不能自动识别全部不适用布局。

相邻原始画面逐像素一致时才考虑停驻；其他画面比较向前配准候选。相似谱行中的小节号也参与比较，避免把不同原谱位置的重复音乐合并。

固定0.5秒采样可能恰好跨越完整的重复系统，使两个采样看起来相同。程序在同一次流式解码中分出运动观察支路，将每个原生帧等比缩至最大128×128，测量相邻原生帧的8位亮度平均绝对差。原始RGB取样支路不经过该缩放或颜色转换。每个采样间隔只保留最大亮度差、原生序号和实际PTS的有界摘要，不新增seek，不保存高频RGB或原生日志。

存在被跳过的原生帧且亮度平均绝对差超过1时，程序要求采样之间的位置可区分。如果多个相隔超过2像素的位移具有同等全局及局部匹配质量，程序返回 `discontinuity`，不靠偏好最小位移选择其中一个。profile层多解时，只有全部有效实际RGB像素在每通道差8以内且仅对应一个位移，才可用局部细节消歧；精确相同的采样也必须经过这项候选检查。这覆盖跨越一个或1.5个重复系统的周期采样别名。

亮度变化本身不证明发生滚动；存在唯一可行位置时，即使背景或播放标记变化，程序仍按该位置接续。取样已包含每个原生帧时保留原有相邻配准，不宣称能恢复源视频在原生帧之间未记录的运动。运动摘要另保留间隔内最大变化的实际原生时间。该变化显著大于端点小图差异时，程序补取该原生画面，避免短暂页在两个相似采样之间消失；此补证共用64次seek预算，无法取证或预算耗尽时失败。缩图和差异阈值仍可能漏掉很小的变化，不构成完整性保证。运动检查保留默认0.5秒间隔；有疑问的区间按下面的有限补帧规则检查，不猜测遗漏的谱行数。

128像素缩图、亮度差1和候选位置相隔2像素是通用启发式边界，不保证检测所有运动。背景或播放标记发生明显变化，也可能触发保守拒绝；很小的运动可能被缩小或阈值漏掉。该观察不能代替SHA-256来源完整性证据或音乐校对。诊断逐行读取并立即丢弃，每次读取最多4096字节。持久采样和运动摘要仍受4097条上限、解码期限和任务磁盘额度约束。结果 `metrics.sampling_interval_seconds` 记录常规RGB间隔，`routine_rgb_frames` 记录常规帧数，`retained_rgb_frames/retained_rgb_bytes` 记录包含尾帧和补帧的实际保留数量与字节，`refinement_rgb_frames` 记录实际补帧写入数。`metrics.native_motion_observations` 记录原生观察数，`samples` 的 `native_motion_max_luma_difference` 记录采样间隔最大变化，`native_intermediate_frames` 记录未保留为RGB的原生中间帧数，最后一个常规采样另记录尾段摘要；`decoded_reported_frames` 仍统计实际返回的采样与读帧记录。

### 画面预检与局部补帧

在完整采样前，程序检查所选区间的七个分散原生时间点，记录实际PTS、time_base、白底比例和五线结构证据。低帧率的多次seek可能返回同一原生帧，记录按原生身份去重。未检测到五线或单点黑屏始终继续完整检查。当前画面预检只会直接拒绝尺寸不足以容纳五线的确定性情况，不声称由少量截图证明整条视频没有鼓谱。结果的 `preflight` 保存这些证据。

配准失败时，程序仅在失败区间按0.25秒、0.1秒补取实际帧，每个原始区间不超过2秒，最多12个区间、64个共享补证预算单位。单帧seek每次计1，连续原生窗口每个返回RGB帧计1。预检和补帧的实际解码时间均计入既有累计解码预算；总期限、临时空间、进程树RSS和取消监督继续生效。补帧不会伪造PTS、改写原来源时间，或按运动速度选择重复音乐的位置。证据不足返回 `discontinuity`。

相邻视口重叠不足四分之一时，只有独立像素墨迹IoU至少0.85、至少128个有效墨迹像素、严格局部内容校验及第三帧实际重叠均支持唯一位置，才可接续。最短重叠为32行或画面高度的8%，取较大者。候选、第三帧位移、有效墨迹和实际补帧区间记录在 `registration` 中。保留位置未知的候选不会用于合成。

### 固定覆盖物与交付边界

自动忽略固定覆盖物默认开启，可用 `--no-ignore-fixed-overlays` 关闭。检测至多检查32个时间分散的画面对，至少三个通过独立内容对齐的非零滚动区间才可提供遮罩证据；暂停画面的静止音符不作为证据。当灰水印压过原始profile时，程序另以暗墨迹建立严格、无歧义的初始位移；中间灰度仅在该启动比较中作为未知区域，不改写RGB。启动比较仍需至少128个有效墨迹像素和0.85的IoU，不能用水印静止推断零位移。两种比较都失败时不生成遮罩。未知区域需在至少80%的已验证滚动比较中稳定，并与位移后的源内容矛盾。profile和独立像素比较共用遮罩；有效重叠或墨迹不足时补证或失败。`registration.invalid_pixels` 和 `overlay_comparisons` 记录检测结果，关闭时均为零。

高饱和度光标和高亮按每帧独立标记为匹配未知区，位置比较排除两帧各自的未知像素。真实彩色记号也可能被排除于匹配，因此剩余证据不足或有多个位置时仍失败。遮罩只影响位置计算，不擦除源RGB、署名、水印或推断被遮住的符号。合成只增加首次观察到的新位置，后续重复音乐保留。

自动选区按各帧占主要比例的浅色纸面背景和多帧连通域生成候选，使用分散原生帧的五线结构验证。灰色工具栏与侧栏不能仅因颜色较浅就并入纸面，也不再因画面八成以上为白底而跳过边界检查。纸面候选保留标题、五线外音符、力度、房子括号和相关文字，不按五线外框裁切交付。较大的空白面板不优先于有持续五线证据的候选；多个候选均有持续证据时返回 `unsupported_layout`。分散点证据不足时继续检查已采样画面，单次或晚出现的谱面不会仅因未命中分散点而被排除。唯一纸面候选没有五线证据时仍交由后续转换确认。候选检查遵守任务期限、资源与取消预算；没有可区分纸面边界的软件布局仍可能失败，手动谱区继续可用。

配准后，同一原谱位置的边缘残片通过后续观测补足，连续合成只交付一次该位置。最终长图外边界仍有触边符干、音符、浅灰或彩色独有记号，或边缘附近有未组成完整五线的平行谱线时返回 `incomplete_score`，不将残片当作完整末行发布。此错误表示覆盖不足，不能据此断言原视频从未显示所缺部分。中途无法建立唯一位置时继续返回带失败秒数的 `discontinuity`，不降级为成功。两种失败都不发布 PDF 或不完整目录，网站保留脱敏原因，整理记录的 `error.conversion_failure` 保存错误类别、时间范围和说明。

自动区域交付前会检查每个实际使用的原生帧。只有两侧均有不超过宽度1%的对称细黑视频边框、内部紧邻白色，才移除这些外部像素；H.264的单列均匀灰色过渡边缘也需逐帧证明。任何帧出现边缘记号或其他变化就保留原区域。匹配区域记录为 `registration.match_region`，交付区域仍为 `region`；原白色页边距、标题和署名保持原样。手动区域不进行这一步裁剪。

彩色记号、水印及播放标记可能保留。清理不能证明隐藏符号正确，结果无警告也不能证明音乐等价。分页仅在检测到的安全空隙间处理完整谱行或连续行组，并保持比例；超高组不得硬切。

A4 默认页边距为12点，约4.23毫米。同一份谱面使用统一比例，按安全完整行组紧凑排列，自动计算行组之间的留白，不横向拉伸或裁断行组；单页短谱仍可能保留底部空白。

合成视频用来验证公开输入、输出保护、来源时间、比例与分页约束，不代替真实谱面质量验收。固定真实集的版本、hash、首轮基线和回归证据由比较工具记录，未知指标保留 null。

默认分页现按安全完整行组紧凑安排，只去除纯白纵向空白，完整保留非白像素和行内几何关系。跨页使用同一比例，自动行间距有上限。不能安全分开的连续边框、非白背景和跨行记号仍整体保留；这些情况及短末页可以有底部空白。此行为替代此前“连续条带保留全部原行距”的分页描述。网站提供独立临时打印设置，见[排版设计](print-layout-design.md)。

## 遮挡恢复与来源追溯

配准成功后，程序只从同一原谱位置的真实无遮挡观测复制像素。固定屏幕水印必须先取得独立滚动配准支持的屏幕覆盖物证据；候选来源坐标必须位于覆盖物掩码外，也不能含未确认的彩色像素。窄竖条光标还须有同形同色条在另一屏幕横坐标出现，并由已配准帧证明原谱对应位置的条已消失；始终存在的真实彩色记号保留。程序不按最白像素、时间中值或投票补出隐藏内容。随谱面移动且始终遮住同一内容的水印保留。没有可用观测的区域保持原像素。

返回值和 `manifest.json` 的 `restoration` 记录恢复像素数、已确认掩码中的未恢复像素数及精确矩形 `blocks`。每块包含来源采样索引、实际 `source_pts`、`source_time_base`、时间、采样 SHA-256、来源坐标 `source_box`、原观测坐标 `original_box`、长图坐标 `target_box` 及证据类型。坐标使用左闭右开的像素边界；来源坐标属于原生帧，目标坐标属于派生长图。未确认覆盖物不计入已确认掩码的剩余像素数，不以零剩余声明谱面完全无遮挡。恢复记录最多包含4096块；继续恢复会超过该上限时，程序保留该候选区域的原像素，设置 `block_limit_reached=true` 并计入未恢复像素。

Python、CLI 和网站共享恢复结果。网站摘要与整理记录保留恢复范围和局限，PDF 与谱面预览只包含谱面，不添加程序生成的说明文字。自动结果仍为 `reliable=false`。网站按原期限清理原生帧和长图后，记录仍可核对采样身份与坐标，但不能只用剩余 PDF 重建原生观测。新增算法源码计入 `program.source_sha256`；视频缓存继续只复用通过版本核验的原始媒体，不复用旧转换结果。

## 自动主曲范围

默认从已采样的实际画面选择一段连续主曲谱面。选择依据包括五线、内部竖线和谱线下方的符号说明结构；短时长和片头、片尾位置本身不能证明可排除。带小节结构的相似谱例与主曲之间出现中断时，返回 `ambiguous_scope` 并提示位置，要求指定范围后重试。遮挡首屏只有在后续真实画面的无遮挡墨迹证明同一谱面时才可替代。结构启发式不识别教学文字的语义，也不保证所有视频均能自动分段。

`conversion.scope.mode` 区分 `main_song` 与 `excerpt`。`scope.requested_range_seconds` 保存请求范围，`scope.effective_range_seconds` 和外层 `conversion.effective_range_seconds` 保存实际采用范围。`scope.excluded_intervals` 保存排除区间、结构原因及对应原始 `samples` 索引；`scope.observations` 保存实际 PTS、time_base 和分类依据。全部原始采样继续登记，不因为排除而丢失来源 hash 或线上清理身份。`conversion.is_excerpt` 只表示用户显式选段，不以自动排除片头片尾冒充完整视频覆盖。

`conversion.effective_region` 保存最终原画面像素区域，与顶层 `region` 相同。网站摘要和整理记录传递同一 `conversion`。`scope_notice` 用于结果页与网站警告。按用户最新要求，PDF 与谱面预览不添加程序的范围、连续性或未经校对说明；原谱自带的文字与记号保留。


### 无重叠翻页与边缘残片

`registration.continuity` 和 `conversion.continuity` 区分 `overlap_verified` 与 `unverified`。后者仅确认视频页序，不能证明上传者未删掉原曲。网站摘要和整理记录继续传递 `conversion` 与 `page_order_unverified` 警告；PDF 和预览不添加程序说明。

重叠细化仍失败后，程序在不超过2秒的局部窗口观察同次解码的原生序列。前后每侧至少两个稳定实际画面、唯一切换边界及完整行边缘必须成立。多解、反向内容接续、回跳、独有短驻留画面或无法确认的过渡动画继续失败。稳定比较还拒绝非unknown区域中独有的可见深色或浅灰记号，不能用全局98%相似度吞掉一个小记号。原生序列的局部PTS回退也保守拒绝，不将其排序为相邻证据。

`registration.transitions` 的 `native_page_cut` 保存实际切换区间、同次序列及相邻原生序号，`adjacent_native_samples` 指向最终 `samples` 清单中的帧hash、PTS和time_base。每个窗口RGB都保存并计入补证预算；`metrics.native_window_calls` 记录窗口数，`native_window_rgb_frames` 记录实际写入RGB数量，`refinement_requests` 在 registration 中记录共享消耗。网站清理原生文件后只保留指纹和观测记录，不能声称还能重建源图。

只有独有局部墨迹在后续完整行中唯一对应时，才替换原屏边缘残片。暗墨迹先定位候选，再核验被删除条带的全部RGB像素，包括浅灰与注册时未知的彩色记号；任一通道差超过8就拒绝替换。实际原生相邻帧及此前可能保留该位置的RGB观测共同参与核验。替换记录保留来源样本、坐标、hash与像素差依据。不能匹配的独有残片继续返回 `incomplete_score`，不以连续性待核对规避失败。

长图按每个独立连续段核验上下边缘。恢复只从同段的可信原谱位置取实际像素，残片替换后的旧段范围不得延伸到新页。

封面叠图只能由后续同位置真实观测替代。除了无遮挡墨迹位置支持外，封面框外每个可见原记号都必须在替代观测中保留，RGB各通道差不得超过8。封面外的独有标题、力度、灰色或彩色文字不能因全图相似度较高而被丢弃；无法证明时返回 `ambiguous_scope`，请指定范围后重试。
