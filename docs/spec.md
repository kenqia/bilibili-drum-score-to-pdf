# B站动态架子鼓谱链接转可打印 PDF skill

状态：待实施。以下需求来自需求访谈；第一版布局边界和测试入口为待确认的实施建议。

## Problem Statement

用户希望将 B站动态架子鼓谱用于打印和练习。视频中的谱面随播放推进，单张截图无法覆盖整曲；多次截图又会带来重复内容、截断的谱行和播放光标。用户需要自行裁剪、判断顺序和分页，难以确认是否漏掉了谱段。

目标是让用户提供视频链接后，自动将视频中已有的谱面整理成可打印曲谱。遇到确实无法判断的内容时，用户只需在聊天中确认对应疑点。

## Solution

提供供当前 Codex Windows/WSL 环境使用的 skill，接受 B站视频链接或本地视频。它检查输入清晰度，提取完整谱行，利用相邻画面的重叠整理顺序，去除重复截图，生成 A4 纵向、白底黑谱的 PDF。

一键还原允许在疑点处请求人工确认。skill 展示编号截图、源视频时间和具体问题，保存处理进度，收到文字回答后继续。无法获取视频或匿名画质不足时，转用用户提供的本地高清视频。无法恢复的内容不得猜补；用户可以补充内容，或明确接受标有缺失位置的结果。

第一版建议以《七里香 周杰伦 动态鼓谱》的白底、多行、纵向推进谱面为支持范围。先验证该样本整曲，再依据实际结果扩展适用范围。

## User Stories

1. 作为练鼓用户，我希望提供 B站视频链接即可开始谱面还原，以便减少手动截图和排版。
2. 作为练鼓用户，我希望提供本地视频也能运行同一流程，以便不依赖网络获取视频。
3. 作为练鼓用户，我希望链接获取失败时收到原因和本地视频兜底说明，以便继续完成转换。
4. 作为练鼓用户，我希望匿名画质不足时被告知需要更清晰的输入，以便避免打印出看不清的鼓谱。
5. 作为练鼓用户，我希望系统区分源视频清晰度和图片放大，以便不会误以为放大能补回音符细节。
6. 作为练鼓用户，我希望系统先判断谱面布局是否适用，以便在无法处理的布局上尽早得到说明。
7. 作为练鼓用户，我希望系统自动找到鼓谱所在区域，以便减少手动指定裁剪范围。
8. 作为练鼓用户，我希望每个保留的谱行都是完整的，以便不会丢掉上下边缘被截断的音符或标记。
9. 作为练鼓用户，我希望系统利用相邻窗口的重叠整理谱行，以便获得按原谱顺序排列的整曲。
10. 作为练鼓用户，我希望同一处谱面停留期间产生的重复截图被去除，以便曲谱不会因采样而重复。
11. 作为练鼓用户，我希望重复段落按实际演奏顺序保留，以便副歌等再次出现的内容不会被误删。
12. 作为练鼓用户，我希望原谱反复记号原样保留，以便维持原作者的记谱表达。
13. 作为练鼓用户，我希望系统优先选取没有播放光标干扰的清晰帧，以便读谱时能看清音符。
14. 作为练鼓用户，我希望处理光标和背景时保留记谱细节，以便符头、符杆、连梁和其他标记不会被误删。
15. 作为练鼓用户，我希望原视频中的标题、速度和拍号得到保留，以便识别曲目并按原谱练习。
16. 作为练鼓用户，我希望得到 A4 纵向、白底黑谱的 PDF，以便直接打印。
17. 作为练鼓用户，我希望分页不切断谱行，以便无需跨页拼读同一行鼓谱。
18. 作为练鼓用户，我希望系统优先保证可读性，再减少页数，以便节省纸张不会损害练习体验。
19. 作为练鼓用户，我希望每个拼接位置能对照源视频核查，以便确认整曲顺序与完整性。
20. 作为练鼓用户，我希望每个疑点带有编号、截图和视频时间，以便准确回答系统的问题。
21. 作为练鼓用户，我希望直接在当前聊天中用文字确认疑点，以便不用学习额外的界面。
22. 作为练鼓用户，我希望等待确认时保存处理进度，以便回答后可以继续。
23. 作为练鼓用户，我希望系统先寻找其他清晰帧再请求帮助，以便减少不必要的人工确认。
24. 作为练鼓用户，我希望无法恢复的内容明确标出，以便知道哪些位置仍需核对。
25. 作为练鼓用户，我希望可以补充缺失内容，以便将曲谱补全后再生成最终 PDF。
26. 作为练鼓用户，我希望可以明确接受标有缺失位置的 PDF，以便在已知限制下使用现有结果。
27. 作为练鼓用户，我希望有缺口的结果不会被称为完整还原，以便正确判断曲谱的可靠程度。
28. 作为练鼓用户，我希望正常输入自动处理，仅在必要疑点处介入，以便一键还原仍能节省操作。
29. 作为练鼓用户，我希望处理过程中看到进度和当前问题，以便判断流程是否仍在运行。
30. 作为练鼓用户，我希望同一本地视频再次处理得到一致的谱面内容与顺序，以便结果可以复核和复用。
31. 作为练鼓用户，我希望知道样本的实际耗时、确认次数和输出页数，以便了解使用成本。
32. 作为 Codex 用户，我希望视频处理在本地完成，当前 Codex 只查看必要的少量谱面截图，以便限制数据流转范围。
33. 作为 Codex 用户，我希望无需配置登录态、外部识别 API 或付费服务，以便保持设置简单。
34. 作为 Codex 用户，我希望先收到可检查的 skill 文件包，以便验证后再处理安装。

## Implementation Decisions

- 采用谱面还原路线，整理已有谱面，不识别音符后重新记谱，也不听音扒谱。
- 第一版运行环境为当前 Codex 的 Windows/WSL。本地视频处理与当前 Codex 查看少量截图相结合，不宣称完全离线。
- 链接输入与本地视频输入进入同一转换流程。公开视频获取不依赖登录态；获取失败或清晰度不足时使用本地视频兜底，不保证所有链接都能获取高清版本。
- 重复截图和重复段落是不同领域概念。只去除重复截图，保留演奏顺序中的重复段落，不自行改写原谱反复记号。
- 从完整谱行组织输出，避免直接按整张采样帧拼接。谱行选择和拼接保留源视频时间信息，用于疑点说明与核查。
- 清理光标或背景以不损失记谱信息为前提。无法可靠恢复的内容进入疑点处理，不猜补音符。
- 等待确认时保留编号疑点、证据和处理进度。用户回答后继续；尚未解决的疑点不得静默视为已确认。
- 默认生成 A4 纵向、白底黑谱 PDF，分页不切断谱行。保留原视频可提供的标题、速度和拍号，优先可读性，再减少页数。
- 对无法恢复的内容，支持用户补充或明确接受带缺失标记的 PDF。有缺口的结果保留对应说明。
- 交付时区分成功、等待用户确认和失败。失败说明原因与可继续使用的输入，不将不完整输出伪装成成功。
- 不接入额外的外部识别 API 或付费服务，不读取或保存真实 Cookie、认证信息或密钥；不输出或持久保存带签名的媒体地址。临时媒体地址仅用于必要的网络读取，不进入交付记录或日志。
- 优先复用已有 ffmpeg、ffprobe、Python 和 uv。具体图像处理与 PDF 依赖尚未选定；新增依赖需说明用途，在独立环境安装并验证，不修改全局 Python 环境。
- 先交付 skill 文件包，验证完成后再处理安装。不在规格阶段修改 Codex 认证、配置或现有技能。
- 第一版以样本的白底、多行、纵向推进谱面为布局边界，这是实施建议。连续滚动与跳行切换的适配需依据完整样本验证；其他布局先判断适用性。
- 不设未经实测的耗时承诺。记录样本处理耗时、人工确认次数和页数。

## Testing Decisions

- 已确认的验收标准是整曲顺序正确，无提取造成的漏行或重复；每个拼接位置可对照源视频检查；A4 不切断谱行，五线、符头和符杆清楚；缺失内容经过用户确认；同一本地视频重复处理时内容和顺序一致。
- 建议采用一个统一转换入口作为主要测试边界。测试提供视频输入和必要的用户回答，检查 PDF、疑点、源视频对应记录及可恢复进度。此测试入口建议尚待用户确认，不预先绑定具体命令名称或参数。
- 测试只断言外部行为。不要依赖内部帧数、阈值、算法步骤、缓存布局或逐字匹配文档。重复运行的一致性比较谱面内容与顺序，不要求 PDF 元数据或文件字节完全相同。
- 覆盖范围包括输入获取与本地兜底、谱面还原、疑点确认与恢复、PDF 排版，但优先从统一入口验证，不为每个内部阶段新增独立测试接口。
- 使用固定本地视频验证还原行为，以减少网络状态和临时媒体地址对结果的影响。链接输入另做实时 smoke check；链接可获取不能替代整曲还原验收。
- 正常路径使用《七里香 周杰伦 动态鼓谱》整曲，核对所有拼接位置、开头和结尾。三张稀疏采样帧不能作为整曲测试夹具。
- 覆盖重复截图与真正重复段落的区别、光标干扰、上下边缘截断、无法恢复的缺失内容，以及确认后继续处理。优先使用真实样本中的对应场景；不足时再增加最小夹具。
- 覆盖链接不可获取、画质不足和不适用布局，确认流程报告原因并提供适当兜底，不虚报成功。
- 对等待确认路径验证：进度被保留、疑点仍可核查、用户回答后能继续、未获确认的缺失内容不会进入声称完整的成品。
- 渲染最终 PDF 并逐页检查分页与可读性，同时对照原视频，防止背景或光标清理删除符头、符杆等信息。不能仅靠页面尺寸或程序退出码判定打印合格。
- 保存实验记录，包括输入来源、实际获取画质、工具和依赖版本、处理耗时、人工确认次数、输出页数及未通过项目。记录不含敏感凭据或带签名媒体地址。
- 当前工作区不是 Git 仓库，没有现有转换实现、测试入口或同类测试可复用。以上是测试计划，尚未运行实现测试、整曲 smoke check 或打印验收，不添加与实现相互复述的测试脚手架。

## Out of Scope

- 听音扒谱、识别音符后重新记谱、生成 MusicXML 或其他可编辑乐谱。
- 第一版保证任意谱面布局、任意视频或跨设备兼容。
- 猜补视频中始终不可见的音符，或通过放大低清图片宣称恢复细节。
- 自动将重复段落压缩成新的反复记号，或改写原作者的记谱。
- 自动登录、读取用户 Cookie、绕过访问限制、修改认证或注入凭据。
- 额外的外部识别 API、付费服务、独立网页确认界面。
- 硬性耗时承诺、未验证的高清获取承诺，以及在验证前自动安装 skill。
- 发布网站、部署服务或批量处理视频。

## Further Notes

验收样本为 [《七里香 周杰伦 动态鼓谱》](https://www.bilibili.com/video/BV1b5411x7Ku)。[B站公开元数据](https://api.bilibili.com/x/web-interface/view?bvid=BV1b5411x7Ku)显示时长 297 秒、一个分P、元数据分辨率 1920×1080。

视频网页读取曾返回 412。依据[公开项目的视频流接口文档](https://github.com/bilibili-plugins/bilibili-api-collect/blob/master/docs/video/videostream_url.md)取得匿名流后，仅对 15、60、120 秒各采样一帧，实际为 640×360。观察到白底、多行鼓谱、纵向推进的谱面窗口、与音符相交的浅蓝色光标，以及上下边缘截断的谱行。尚不能凭三帧区分连续滚动与跳行切换，也未验证高清获取、整曲覆盖、光标清理和打印质量。

本规格以需求访谈的已确认内容为依据。现有领域术语包括谱面还原、可打印曲谱、疑点、一键还原、重复截图和重复段落。当前没有已记录的 ADR，不把未验证的算法或依赖写成已定架构。
