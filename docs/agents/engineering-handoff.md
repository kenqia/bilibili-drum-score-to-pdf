# 工程交接

工程续跑读取任务指定证据目录中的 `CURRENT.md`；未指定时使用仓库 `work/engineering/CURRENT.md`。已有外部证据目录可以在此路径建立本地符号链接。再核对工作区分支、HEAD 和 Git 状态。`CURRENT.md` 保存当前事实，`HISTORY.md` 保存已发生事件；旧日志只作为历史证据，不作为下一步指令。谱面任务仍以 `record.json` 为准。

## 更新当前状态

在阶段完成、等待工具或跨轮次交接前，覆盖更新 `CURRENT.md`。写入以下内容：

- 更新时间、目标、仓库绝对路径、工作区分支和完整 HEAD。
- 当前阶段、下一步和真实阻塞。完成、运行中和失败分别记录。
- 仍在运行的任务，以及回执中的工具名称、进程或 session ID。只用当前工具声明支持的等待操作。
- 用户已授权的操作范围。授权不能从历史推测；后续指令可以撤销或收窄授权。
- 最近验证命令、结果、对应提交和证据路径。未知或未运行的验证如实标记。
- 需要保留的用户修改、实验和任务目录。

每次更新把阶段结果追加到 `HISTORY.md`，只保存时间、事件和证据引用。初次转换旧交接时保留原文件，并在旧文件顶部指出当前状态的位置。写入当前状态前核对 Git 与工具回执，不能把派发成功写成实施或审阅完成。

## 恢复核对

1. 读取 `CURRENT.md`，执行 `git branch --show-current`、`git rev-parse HEAD` 和 `git status --short`。
2. 对不一致的提交、任务或结果读取对应证据，更新当前事实。
3. 从下一步继续。只在依赖它时读取历史；失败任务按实际 ID 和当前工具声明恢复。

交接完成的标准是接手者能确定当前提交、已完成结果、授权范围和唯一下一步。日志中的旧成功不替代当前验证，也不解除真实来源的 `blocked`。
