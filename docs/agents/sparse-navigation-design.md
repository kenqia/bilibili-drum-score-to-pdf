## 默认流程

1. 准备新任务，复用现有匿名获取、来源完整性及资源保护。
2. 观察视频开头和结尾，记录实际 PTS、谱面布局、音乐起止及相关疑点。视频端点不直接等同于首条或末条音乐内容。
3. 稀疏跳转，识别完整谱行并更新清单。重复过多时扩大跨度，接续不足时缩小跨度或回到疑点区间。
4. 通过唯一重叠、可信滚动关系或编号接续证据连接谱行。没有依据时保存未决连接。
5. 对疑点局部加密，必要时使用现有连续扫描。程序无法判断时返回相关原生来源，供 Agent 查看并记录决定。
6. 来源及接续通过后选取合格来源、冻结粗拼，沿用现有分组生图、一次修正及矢量兜底。
7. 独立排版 A4 PDF，检查全部页面后交付。

当前程序没有小节号识别能力。Q2 不意味着程序已能读取编号；使用 Agent 实际读取的编号时，须记录判断者、对应来源和依据，不能从几何检查或空编号推断确认。新 OCR 或模型服务不是本轮已确定的依赖。

## 谱行清单

`row_manifest` 持久保存以下信息，并与现有 `regions`、截图和输入版本建立对应关系：

- 稳定谱行身份、原谱位置、独立的排列顺序。
- 来源截图引用、hash、实际时间戳、PTS、time_base 和裁剪区域。
- 完整性、清晰度或遮挡风险、备用来源、当前选择及选择原因。
- 前后接续依据、判断者、关联来源和未决事项。

同位置来源可以替换为更清楚的合格来源，旧来源证据保留。不同原谱位置的相同音乐必须保留。补采插入候选时，现有谱行身份保持稳定；身份不能由候选索引或当前排序重新生成。

清单元数据变化可以触发资格复查，但只有实际组输入或组成员变化才使对应生图组失效。更换实际来源需沿用现有输入版本及额度规则，不能以清单更新为由重置调用预算。

## 证据与冻结

分别记录以下状态：

- 接续证据是否完整。
- 严格时间覆盖的实际区间及是否完成。
- 未决事项及其影响范围。

稀疏接续证据完整、首尾及裁剪检查通过时，允许冻结并推进后续流程，即使严格全曲时间覆盖尚未完成。未解决的来源位置、音乐和裁剪问题阻止批准。

稀疏观察不证明未采样时间里没有短暂换页。首尾同图也不能据此证明中间没有 A→B→A。发现回跳、编号冲突或其他风险时补查；无法证明时保留未决。严格时间覆盖仅由实际连续扫描产生，稀疏截图不能写成已连续观察区间。

## 兼容、文档与验证

保留显式严格连续扫描及其现有公开能力，不把正常稀疏导航悄悄升级为整曲逐帧扫描。保留有效历史冻结及现有恢复约束，不自动迁移旧任务。

Skill 修改以 main 的自包含包为基础。修改 `docs/agents/` 文档源后，通过 `tools/sync_skill_references.py` 同步 `references/`，并执行同步检查。新增或改变的公开入口纳入 `tests/test_public_contracts.py` 共同约束矩阵。
