# Agent 的截图、重绘与 PDF 工作流

`score_workflow.py` 是新版工作流接口。用户提供公开 B站链接或本地视频，Agent 负责导航、看图、确认接续、调用真实宿主生图并审阅 PDF。用户无需选择路线或填写任务 JSON。`convert.py` 默认 prepare 使用本接口；命令参数见[新版入口](reconstruction-entry.md)。

选行、重绘失效、恢复校验和记录发布统一由 `score_task.py` 管理。本页的函数名、参数和任务格式保持不变；调用方无需访问几何实现的私有函数或自行清空派生产物。

正常流程在 prepare 后调用 `stage`，先检查首尾与布局，优先读取行首小节号，再按已证明的新增完整谱行及接续稀疏跳转；自动检查通过的来源无需 Agent 生图前复看。`row-manifest` 查看稳定谱行与来源，编号接续经 Agent 实际查看后用 `review-continuity` 登记。稀疏接续资格与严格时间覆盖分别记录，普通视频不先运行全曲连续扫描。阶段响应、局部版本恢复及全部预览读取[阶段说明](stage-recovery-layout.md)。以下低层操作用于补采、人工来源判断和异常恢复。

## 准备与采集

使用项目现有 `requirements.txt`、`ffmpeg` 和 `ffprobe`。最终逐页检查使用 Poppler。没有新增模型认证、付费 API 或依赖。

1. 调用 `prepare(source, task)`，其中 `task` 是新的空目录。公开 URL 沿用匿名下载、分 P、网络校验、下载期限与媒体资源保护。本地视频与 URL 在获取后使用同一任务记录。恢复时再次传入同一视频或等价的规范 URL，不会重复下载。
2. 调用 `navigate(task, seconds, width=480)` 保存低清导航图。实际查看导航图，判断谱面是否推进，然后决定下一次导航时间。时间由 Agent 根据画面决定，不使用固定采样间隔。
3. 对主要推进位置调用 `capture(task, seconds)` 保留原生截图。截图记录实际 PTS。静态停留和光标移动不要求继续保留原生截图。发现缺口时，有目的地补采缺失位置；稀疏回查连续两次无收益就停止二分并交给 Agent，次数跨恢复累计；未解决不能放行。
4. 实际查看原生图，用 `present(task, identifiers, notes)` 记录已呈交的截图或导航图。低清探测、原生截图与实际呈交数量分别保存。保存文件不等于看过图。

## 确认接续并粗拼

调用 `assemble(task, title, regions, review)`。`regions` 使用[本地工作流的裁剪字段](reconstruction-local.md)，并增加每个原谱空间位置的 `position` 字符串。相同位置的重复截图只保留第一项；后续出现的重复音乐使用另一个位置标签。标签由 Agent 看图提出，不从像素相似度推导。

`review` 除已查看来源、完整性和具体备注外，必须记录 `continuity` 与 `first_last`。确认相邻截图重叠、上滚或有序翻页接续，检查视频前后无谱区间和最后完整谱行。半行在取得完整来源之前不能纳入。标题、速度、拍号、行外记号与短末行也要保留。水印、高亮或蓝色播放矩形本身不会导致拒绝；遮住关键内容时记录 `unresolved`，局部补采后再确认。

不能确认的接续应保持 `complete=False` 或填写 `unresolved`，程序不生成成功 PDF。片段演示在记录中明确 `scope`，不能称为整曲交付。原裁剪保留完整；粗拼根据内存像素边界分块，`rough_chunks` 按原谱顺序列出全部材料。

## 调用宿主生图

调用 `redraw_inputs(task)`，取得按完整谱行划分的可审阅输入页。必要时传入 `groups`，每个分组是一组连续 region 索引，全部分组必须按顺序覆盖全部材料。默认和显式新分组均受八条完整谱行、粗拼像素上限和拟合 4096 像素长边后至少 4 像素五线间距的约束。超限时拆分完整行；单行自身不足时补采更清晰来源。相同身份的历史材料恢复保留调用与修正额度。

对每页依次执行以下操作。

1. 实际查看粗拼输入。调用 `begin_redraw(task, page_id, viewed_notes)`，先保存请求和输入 hash。
2. 调用真实宿主 `image_gen`，以返回的输入路径作为编辑来源。要求保留原图的音符、谱位、节奏、符梁、附点、鼓谱符头、标题与关键记号。程序只管理产物与状态，不代替宿主执行模型调用。
3. 工具返回后调用 `finish_redraw(task, page_id, request, output_path, 'host-imagegen', receipt)`。`receipt` 记录此次真实调用的标识和来源。复制原有 PNG 或受控 mock 不能计入真实生图验收。
4. 实际查看输出图。合格时调用 `review_redraw(..., accepted=True, notes=..., boundaries=...)`。`boundaries` 是输出图中每个完整标题块或谱行的整数边界，数量必须等于该输入页的 regions 数量，不能重叠或越界。
5. 初次不合格时调用 `review_redraw(..., accepted=False, notes=具体差异)`，随后调用 `begin_redraw(..., correction=True)`，执行一次定向修正。修正预算在工具调用之前保存，中断不会重置。修正后仍不合格，审阅接口自动将该页标记为 `vector`。

宿主不可用、调用失败或中断后无法确认调用结果时，调用 `fail_redraw(task, page_id, notes)` 转入矢量兜底。已接受的输出不能被迟到的失败记录降级。同一任务可以混合使用生图与矢量路线。

已接受的图像在后续独立核查或最终 PDF 审阅中发现实际谱面错误时，调用 `reject_accepted_redraw(task, page_id, notes)`。`notes` 必须描述实际观察到的差异，例如第 59 小节脚踩镲的叉形符头被改成底鼓椭圆。接口只接受当前状态为 `accepted` 的页，空白备注和重复撤回均拒绝。

撤回记录保存在该页的 `rejections` 中，关联被拒绝的生成图、当时的修正次数，以及已有 PDF 的路径、hash 和审阅结果。原生成尝试、先前审阅和旧 PDF 文件继续保留。当前 PDF 引用与批准状态失效；需要重新导出并逐页审阅。没有使用修正预算时，该页转入 `needs_correction`，按上面的宿主流程执行一次定向修正。已使用一次修正时，该页直接转入 `vector`。恢复任务或重新确认相同选行不会退还修正预算。普通 `fail_redraw` 仍不能降级已接受输出。


## 重排、逐页审阅与恢复

所有页处于 `accepted` 或 `vector` 后，调用 `export(task)`。矢量页沿用轮廓与五线转描；生图页按实际确认的完整边界裁切显示。PDF 用裁切和比例变换嵌入原生输出，不先重采样图片。两条路线以原来源谱行宽度作为共同排版坐标，生成图输出分辨率不同也保持相同打印宽度；短来源行保留其短宽度。生成图高度按实际边界比例换算，不重采样或纵向拉伸。程序计算 A4 纵向分页，在完整谱行之间分页。稀疏页限制间距并平衡上下留白，不拉伸谱行或生成额外音乐。

输出保存到 `exports/<revision>/<实际谱名>.pdf`，同目录的 `materials.json` 记录来源、路线与最终放置。导出自动使用 `pdftoppm` 保存全部有序预览，实际查看每页，检查顺序、标题、速度、拍号、关键细节、首尾、裁断、重叠与留白。最后调用 `review_pdf(task, pages, notes, output_revision=当前导出回执的output_revision)`，`pages` 必须列出每页。程序完整性检查与实际看图陈述分别保存。

恢复时保留原视频、任务目录与引用产物。读取会验证原视频、截图、导航图、粗拼、生成图、矢量记录和 PDF 的 hash；改变或损坏的材料不复用。相同标题、位置、裁剪和五线参数的 `assemble` 重入保留已经接受的生图、修正次数与 PDF。改变材料或撤回完整性确认后停止导出并撤销当前 PDF 审核，保留同输入的生成尝试与修正预算；重新确认相同来源后继续原有重绘状态。材料改变时重新建立派生产物，旧文件仍保留。排版版本升级只重新导出 PDF，复用已经接受的生成图与修正预算。任务不兼容旧 workflow 格式。模型成本未知时保持 `null`。

选行变更先验证并写入新的裁剪和粗拼文件，再将选行与旧重绘失效状态一起原子保存到 `record.json`。验证失败或记录发布中断时，原任务记录仍有效；未发布的新文件不会成为恢复输入。重复确认成功发布的相同选行才保留已接受生成图和修正预算。

`review_pdf` 在批准最终 PDF 前验证整个工作流的来源、导航图、裁剪、重绘输入、所有已保存生成尝试和导出文件 hash。引用损坏时拒绝批准，不改变任务记录。

## 阶段入口与恢复

准备后使用 `stage` 自动推进至宿主调用或实际审阅；局部来源版本、输入额度恢复、打印布局和全部页面预览见[阶段入口、局部恢复与打印布局](stage-recovery-layout.md)。`layout` 修改边距、最小行距和目标页数，复用已接受生成结果；最终审阅显式绑定当前导出回执的独立 `output_revision`，PDF hash 用于完整性校验。程序检查与实际看图分别记录。
