## 材料与实际视觉过程

`source.musicxml` 是自建三小节鼓谱，`create_score.py` 保留生成记录。用前次实测的隔离 MuseScore 3.2.3 排出原生矢量 `full-score.pdf`，Poppler 全页渲染为 `full-score.png`。这里的 PNG 是受控源谱的渲染，没有视频 PTS，也没有把它冒充视频原截图。该源谱与 PDF 为同一份自建材料，属于小型完整谱例，而不是从视频重绘的产品验收。

实现 Agent 实际查看完整原生谱页和完整 PDF 渲染，逐项检查图例、三个写下小节及所有声部、速度、拍号、三连音、附点、装饰音、力度、反复与尾部休止。根 Agent 另只看全页渲染，在没有读取实现 Agent 转写与 MusicXML 的情况下独立转写音乐事件，保存 `independent-review.md` 与 `independent-events.json`。代码原始谱源没有作为预期事件直接输入 MIDI 比较。`transcription.json` 来自实现 Agent 视觉转写，再与根 Agent 的独立原图阅读比较。

第一次排版的长图例裁切，第二小节速度被图例占位隐藏，实际实看发现后改为分行图例和将速度 160 放在第二小节下方。音乐内容未改。另独立校对指出最后一个军鼓三连音的释放会与前置 grace 同鼓件重叠。没有静默裁短或放宽 note-on/off 校验，改为在谱例公开图例增加释放政策，双方重新看完整页并据此更新播放时长。最终全页图例完整，首尾未裁切。

## 完整音乐内容

图例明确底鼓 GM36、军鼓 GM38、开放踩镲 GM46、crash GM49。首次未标力度 96，f 为 112，p 为 64，grace 为 48。反复回到第一小节时恢复 velocity 96，谱上明确写明这个政策。

第一小节是 4/4、四分速度 120。上声部开头三个军鼓八分三连音，拍点 0、1/3、2/3；随后一粒斜线军鼓装饰音、军鼓附点八分和十六分、两个开放踩镲八分及 crash 四分。下声部是第 0 和 2 拍两个底鼓四分，中间及末拍有明确四分休止。合计 11 次击打，含 grace。

第二小节改为 3/4、四分速度 160，f。两个军鼓四分和一拍休止，合计两次击打。左边第一个小节和第二小节末端的反复记号将前两小节演奏两次。

第三小节改回 4/4、速度 100，p。整小节休止，末端终止线。完整展开次序 1、2、1、2、3，总拍数 4+3+4+3+4=18。末四拍静默保留，不能用最后一次 note-off 代替整曲长度。

grace 在主音前 1/16 个四分拍开始，播放时长 1/16。该音的主音是第一小节第 1 拍。前一军鼓三连音起拍 2/3，记谱时值仍 1/3，按图例播放释放缩短到 grace 的 15/16 起拍，因此播放 gate 为 13/48。这一政策在原谱文本、转写 policy 与独立审核中公开，未将播放 gate 冒充原记谱时值。底层序列化器仍拒绝没有明确处理的同鼓件重叠。
