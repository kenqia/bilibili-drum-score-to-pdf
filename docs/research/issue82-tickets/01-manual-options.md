## What to build

用户在默认折叠的高级选项中填写处理起止时间，选择自动或手动指定谱区，提交后得到对应谱面。本站不提供来源视频预览，用户自行在 B站查看后填写。原目标分 P 超过600秒时在媒体下载前拒绝，选择短区间不能绕过限制。

本票合并原 T2、T3、T4，参数从网页贯通提交、队列、worker、重试与产物记录。默认提交继续兼容。遵守 #82 的独立产品边界，不改变独立 Skill。

## Acceptance criteria

- [ ] 下载前使用已验证元数据拒绝原目标分 P 超过600秒的来源；恰好600秒可进入后续处理。选段不能绕过；实际媒体完整性检查继续保留。
- [ ] 复用现有匿名后端检查来源完整性及支持格式，不按标题、简介或分 P 名称判断内容相关性。
- [ ] 高级选项默认折叠；开始默认零、结束留空表示结尾，默认自动谱区。手动区域采用相对完整画面的边界数值，清楚标明单位和坐标基准；不提供来源播放器、预览准备或拖拽框选。
- [ ] 基础类型与范围在提交时校验，实际时长、尺寸已知后核验有效区间和矩形；非有限值、越界、空区间和反向边界明确拒绝。
- [ ] Python、CLI 与 HTTP 适用入口支持一致的转换参数语义，队列领取与重试保持参数，结果标记实际选段与手动区域，不将选段称为完整原曲，不伪造原生 PTS/time_base。
- [ ] 合成真实视频转换证明首尾、原谱位置、完整谱行、原行距、统一比例、来源 hash 和输出不覆盖继续成立，结果仍 reliable=false。
- [ ] 每类实际失败修复按 TDD 推进：至少核验一个真实案例并复现，先建立能捕获问题的失败验证，再修改并确认该实际案例改善；附修改前后证据。合成测试可以承接真实问题的回归，但不能替代真实案例复现。未复现不得声称修复完成。
- [ ] 沿用公开契约与真实 worker 测试，验证默认兼容、参数传递、重试和错误提示。如需持久化 schema 变更，提供显式升级、备份恢复和兼容回滚验证，不隐式迁移。
- [ ] 更新使用与转换契约文档，保留并行进行的打印版式修改，不执行推送或生产部署。
