## 已确认的产品范围

首批用户已经使用 Codex 等视觉 Agent，愿意安装 Skill。输入是视频中已有的固定比例、白底多行鼓谱。向上滚动需有可靠重叠，有序翻页需能确认前后接续。横向滚动、缩放、回跳与没有谱面的演奏视频不在当前范围内。

Agent 自主交付要求用户提供输入和输出位置后，无需纠错或催促，Agent 自行审阅、补采、恢复并交付正确 PDF。正常工具授权不计用户干预。用户重新发起、纠错后成功和旧任务恢复另列。prepare 的 waiting 只是中间状态；最终交付必须完成来源、整曲顺序与每页 PDF 检查。

用户报告以往 Agent 几乎每次能完成且没有改代码，这是使用经验。历史样本分母、干预与失败没有完整整理，不能换算成成功率。本轮最终测试提供新的冻结尝试记录，也暴露了未完成项。产品范围见 [ADR](adr/0001-skill-release-scope.md)，术语见 [领域术语](../GLOSSARY.md)。

## 性能账本的用途与限制

Token 可从 Codex Desktop 的 `token_usage_record.usage` 白名单读取。本轮按线程、root turn、实际调用窗口采集并去重，保存已记录输入、输出、缓存与推理子项，没有导出认证或聊天正文。错误绑定得到的零事件包不能视为零消耗。具体数值见测试报告，口径见 [宿主计量](agents/host-usage.md)。

现有 collector 的完整生命周期、模型调用、工具和图像覆盖都为 false，总模型成本仍为 null。账本可用于查重复分析、补采、操作失败和部分响应用量。本次存在墙钟异常、环境中断、两处短暂试次窗口重叠及提前停止，未得到合格的完整端到端质量及总成本 A/B。

此前 Token 核查专项 16 项通过，63.816 秒，完整架构回归另列。历史 full 与恢复交付也继续保留，但不合并成新批次的成功数，不用恢复成本代替冷启动成本。
