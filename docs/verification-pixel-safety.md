# 微弱残线与彩色裁剪验证

2026-10-07 规格审阅发现两项可通过统一 CLI 复现的漏谱路径。基线为 `8998b5a`，测试使用既有独立绘制谱面和真实 H.264 视频，不读取平台凭据或真实用户数据。

在既有 `card()` 上绘制灰度为 `#383838`、宽 2 像素的线段 `(100,220)..(1180,220)`，随后接 `window('ABC')`，旧实现返回 `success`、`complete=true`，并把该边缘记录为忽略的片头。清晰文字通过分类，但文字前景使用的 35 级对比门槛排除了这条微弱残线。水平线检查现独立采用背景灰度差超过 2 级的信号；清晰标题文字不再抵消微弱谱面信号。首尾成对反例应保持等待，原有纯色及清晰标题仍应完成。

在 `score_frame()` 末行下方绘制黄色椭圆 `(650,805)..(664,819)`，颜色为 RGB `255,255,0`，旧实现同样返回完整成功。末行 bbox 为 `[70,585,1211,777]`，黄色记号全部在裁剪外。裁剪原先只把灰度小于 180 的像素视为墨迹，现增加比较掩码已有的彩色判据，RGB 极差超过 20 且最小通道小于 220。该掩码只确定裁剪空隙和边界，不修改源像素；最终图像仍来自真实帧并直接转灰度。
